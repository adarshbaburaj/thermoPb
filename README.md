# thermopb

**The new way of networking.**

**RTM — Route To Meeting**

thermopb finds a sourced route from a founder to the person they want to meet: a trusted introduction, a shared event, or a reviewed outreach draft. This first implementation is a local, persistent demo of the Tracekit developer-tool story.

This build is intentionally a sample product demo for a video. It runs without provider keys and uses fictional people, relationships, events, and creator posts. Claude remains the intended future AI provider; no live integration is needed for this demo.

## Recording the demo

The app opens in **Chat**. Ask “Who can introduce me to Maya Chen?” to show a short thinking sequence and an answer with a route preview. **Explore in Glass Brain** opens the selected target; return to **Chat** to keep the conversation. **Dashboard** opens the connector overview, where you can search people and explore the introductions they enable.

Chat answers are composed from the staged workspace data, not a live model. It supports introductions, events, creative outreach, TM tags, and a pipeline overview. The thinking sequence represents the demo workflow. No API keys are needed.

In **Settings**, use **Reset workspace** before a new take and **Undo reset** to restore the previous state. No video is generated by the app.

1. **Intake:** build the Tracekit example ICP, accept an expansion, then discover the sample prospects.
2. **Glass Brain:** show Maya Chen’s three-hop route and open a hop’s evidence.
3. **My network:** show your Thermo ID, `TM-ADARSH`. Select `TM-PRIYA`, click **Connect**, then **Accept in demo**. Three introduction opportunities appear, along with a popup saying Priya knows Maya.
4. **Outreach ideas:** click **Run demo lookout** to reveal two new sample techniques. Save one, open its sample post, and choose **Try this approach**.
5. **Routes & queue:** prepare a draft. Add “Your team doubled revenue last quarter.” and click **Review draft** to demonstrate the unsupported claim gate. Remove that sentence, review, and approve the local draft.
6. **Event radar:** show the Platform Engineering Salon and download its calendar file.
7. **Pipeline:** record a sample stage change and show the activity log and route chart.

For the three-target **Unlock score** moment, reset first and use **Try the Priya demo** in the manual capture form instead of accepting her Thermo ID first. Both actions create the same sample connection, so repeating the second action correctly shows no additional unlocks.

## Run locally

Requires Python 3.10+, Node.js 20.9+, and npm.

```sh
python3 -m venv .venv
.venv/bin/pip install -r api/requirements.txt
npm --prefix web ci
./scripts/dev.sh
```

Open <http://127.0.0.1:3000>. API documentation is available at <http://127.0.0.1:8000/docs>.

The launcher works from any current directory, defaults to `DEMO_MODE=1`, and stops both servers on Ctrl+C. It uses the repository `.venv` when present and falls back to `python3`. It does not install dependencies or reset saved data.

To run the services separately, use two terminals from the repository root:

```sh
DEMO_MODE=1 .venv/bin/python -m uvicorn api.main:app --reload --host 127.0.0.1 --port 8000
```

```sh
npm --prefix web run dev -- --port 3000
```

Optional settings are listed in `.env.example`. Copy it to `.env` to use them with the launcher. `API_URL` controls the web server's API proxy and defaults to `http://127.0.0.1:8000`. `THERMOPB_DB_PATH` selects a separate SQLite file; the default is `api/data/thermopb.sqlite3`. For example:

```sh
THERMOPB_DB_PATH=/tmp/thermopb-review.sqlite3 ./scripts/dev.sh
```

## What works

- Product intake saves your paragraph and displays the illustrative Tracekit ICP, confidence bars, and expansion segments.
- Discovery displays 20 fictional technical buyers with source records, fit scores, and tiers.
- Glass Brain shows sourced graph relationships, inferred edges, and ranked paths of up to four hops.
- Network capture and CSV import add the direct relationship you confirm. Capturing the seeded Priya profile improves three target paths because those relationships already exist in the fixture.
- Thermo ID has a staged connection request, explicit simulated acceptance, shared relationship cards, and introduction popups. Demo IDs are `TM-PRIYA` and `TM-ELENA`.
- Outreach ideas includes six fictional creator posts, sample reported outcomes, saved techniques, and planning guidance in the outreach studio. The staged lookout reveals two new ideas; it does not search the live web.
- Event Radar shows three fictional upcoming platform events and downloads labeled calendar entries.
- Route planning compares introductions, events, cold outreach, and the cake concept. Scores are illustrative, not calibrated reply probabilities.
- Outreach drafts are reviewed before local approval. Unsupported factual edits block approval. Approval queues a draft locally.
- Pipeline stages, captures, drafts, approval records, audit events, and local demo credits persist in SQLite across restarts.
- Demo reset and restore make the story repeatable for recording.

The current UI follows [DESIGN.md](DESIGN.md): a light lavender palette, system typography, and a bottom-center navigation dock. Chat adds rounded conversation cards and a contextual rail inspired by the supplied reference. Simple, Advanced, and Creative workspace modes remain available.

## Demo boundaries

All target people, companies, signals, relationships, and events are fictional and link to clearly labeled local evidence. “Extracted” means stated in a fixture; it does not claim independent verification. The dates are anchored to the November 24, 2026 build plan.

Live integrations are **not implemented or connected**: Claude or another LLM, Tavily, Hunter, Neo4j Aura, Moss, Band, Flexprice, Telegram, email delivery, founder-skill tools, and Cold Caked/cakeMCP. The graph is rendered from the shared JSON in the app; Graphify entity Markdown is included, but the Graphify runtime is not integrated.

The current substitutes are deterministic fixture intake/discovery, local graph traversal, conservative exact-sentence evidence review, token-overlap sameness checking, local agent activity, and simulated credits. No real message, Telegram alert, payment, cake order, travel booking, or calendar write is performed. Calendar export only downloads a file. Cake coverage is unconfirmed and no checkout URL is fabricated.

Setting `DEMO_MODE=0` does not enable live services; fixture-backed operations return an unavailable response. Provider keys alone do not activate adapters. Approval never claims delivery or moves a target to Contacted automatically; a user can record actual manual outreach through the pipeline control.

The app has no authentication and is intended for a local demonstration. Live adapters, identity/access control, provider-backed review, and delivery verification remain future work.

## Verify

```sh
.venv/bin/python -m unittest discover -s api/tests -v
npm --prefix web run typecheck
npm --prefix web run build
npm --prefix web run test:e2e
```

Browser tests require the Playwright Chromium browser. If it is missing, install it once from `web/`:

```sh
cd web
npx playwright install chromium
```

## Repository

| Path | Purpose |
| --- | --- |
| `web/` | Next.js interface and API proxy |
| `api/` | FastAPI, deterministic graph writes, paths, review, credits, and SQLite state |
| `fixtures/seed.json` | Shared combined demo seed |
| `fixtures/evidence/` | Explicitly fictional evidence records |
| `fixtures/Connections.csv` | Sample LinkedIn-export column shape with fictional contacts |
| `gtm/` | Linked entity Markdown for Graphify workflows |
| `scripts/dev.sh` | Local launcher |
| `scripts/seed_fixtures.py` | Deterministic fixture generator |

Regenerate fixture files with `python3 scripts/seed_fixtures.py`. This updates source fixtures and entity Markdown; it does not overwrite the existing SQLite demo state. Use a different `THERMOPB_DB_PATH` to start a separate demo workspace without deleting saved work.
